# 2.2 Wayfinders (Capability Discovery)

On-screen prompts and affordances that reveal what an AI agent can do in the current context, turning blank states into clear, actionable starting points.

*Last updated December 2025*

---

## Overview

Wayfinders are UI elements that surface an AI agent’s capabilities in a clear, concrete, and contextual way. They typically appear where an AI assistant is present but no task has started yet: empty states, first-run experiences, “new integration connected” moments, or idle side panels.

Instead of presenting a blank prompt and expecting users to invent a task, wayfinders provide suggested actions, starter prompts, and capability “chips” that are grounded in real data and workflows. The pattern reduces guesswork, aligns expectations with what the agent actually supports, and accelerates time-to-value while building trust.

**Example Placeholder – Embedded Scenario**

> An enterprise account-management assistant loads alongside a CRM account list. The empty assistant panel shows:
>
> * Chips: “Summarize this account,” “Find risks in this opportunity,” “Draft follow-up email.”
> * A short line of context: “Based on Salesforce + email data connected.”
> * When the user selects multiple accounts, the chips update to: “Summarize this week’s at-risk accounts,” “Generate outreach plan for selected accounts.”
>
> The page-level layout could include:
>
> * A collapsible AI side panel on the right
> * An empty-state card inside the panel with three high-value prompts
> * Hover states showing a brief explanation and data sources used for each prompt
> * Optional “Show more ideas” affordance to expand to advanced tasks

---

## Problem

Without explicit guidance, AI interfaces often present a blank input and an abstract promise: “Ask me anything.” This creates friction and undermines trust, especially in professional workflows.

* Users lack a clear mental model of the agent’s scope and limitations, leading to over-trust (“it can do everything”) or under-trust (“it probably cannot help with this”).
* Blank prompts increase cognitive load; users must invent tasks, phrase them correctly, and infer what data the agent can use.
* Misaligned expectations drive frustration: users try unsupported tasks, receive weak or blocked responses, and conclude the system is unreliable or “dumb.”

By explicitly surfacing concrete, context-aware capabilities, wayfinders transform uncertainty into guided exploration and set realistic boundaries for what the agent can do.

---

## When to Use This Pattern

* When introducing an AI assistant into an existing product where users already have established workflows and expectations.
* On first-run or early-session experiences, when the agent’s role and capabilities are not yet familiar.
* After key configuration events: data sources connected, permissions granted, or integrations enabled (e.g., CRM, ticketing, documents, analytics).
* In spaces that otherwise appear “empty” to the user: no prior chats, no configured workflows, no search results, or newly created projects.
* When the agent’s capabilities are broad or multi-modal and require guidance to prevent misuse or overwhelm.

## Probably Overkill When...

* The AI feature has a narrow, deterministic scope and is already clearly described by a single labeled control (e.g., “Auto-format this table”).
* The surrounding UI already provides explicit, highly visible task entry points and there is little ambiguity about what the AI can affect.
* The task is high-frequency and well-learned, such that additional prompts or chips would add clutter rather than clarity.
* The AI executes a single embedded function within a traditional flow (e.g., autocompleting a form field) rather than acting as a general-purpose agent.

---

## Pattern Anatomy

Wayfinders typically appear as lightweight, contextual scaffolding around an AI agent, not as a separate full-screen experience. They often live in panels, empty states, dropdowns, or inline action areas.

### Entry Points

* **Primary entry point:**

  * AI sidebar or assistant panel opened from main navigation or a persistent “Ask AI” button.
  * Empty state when opening the AI assistant for the first time in a module (e.g., Accounts, Tickets, Reports).
* **Secondary entry point:**

  * Inline prompts in relevant components: empty search results, empty tables, report pages, document viewers.
  * Assistant “hint row” at the top of a chat history or reply composer.
* **Contextual entry point:**

  * Banners or toasts after configuration events (e.g., “Jira connected – try: ‘Summarize sprint progress’”).
  * Inline suggestions shown immediately after a user action (e.g., selecting items in a list, uploading a file, filtering a dashboard).

### Core Item / Object

The core repeated unit in this pattern is a **wayfinder suggestion**, often presented as a chip, card, or list item.

* **Label**

  * A concise task-oriented action that names the outcome, not the internal capability.
  * Example: “Summarize sprint progress,” “Find blocked tickets,” “Draft follow-up to this customer,” “Explain this chart.”
* **Description / statement**

  * A short line clarifying what the agent will do and what data it will use.
  * Example: “Uses Jira sprint data from the last 2 weeks,” “Based on this document + recent emails,” “Analyzes selected accounts only.”
* **Controls**

  * Primary: Click/tap to insert or execute the prompt.
  * Optional:

    * “Edit prompt” or inline input to tweak wording before sending.
    * “More like this” to surface similar tasks.
    * “Hide / Not relevant” to train future suggestions.
* **Optional metadata**

  * Scope indicators: data sources, environments, or segments affected (e.g., “Data: Salesforce + Gmail”, “Scope: selected issues”).
  * Safety cues: “Preview only,” “No changes will be applied until confirmed.”
  * Status tags: “New,” “Recommended,” “Advanced.”
  * Usage signals: “Popular in sales teams,” “Frequently used in this workspace.”

## Behavior & Lifecycle

1. **Initial state (pre-usage / empty state)**

   * When the AI assistant is first opened or a relevant module has no prior AI activity, a small set of high-value, low-risk suggestions is displayed.
   * Suggestions are grounded in default or globally available data sources (e.g., “Summarize my open tickets,” “Review last week’s analytics”).

2. **Contextual adaptation**

   * As the user performs actions (selecting records, filtering a view, opening a document, uploading a file), suggestions adapt to reflect that specific context.
   * Examples:

     * After selecting multiple accounts: “Identify churn risk across selected accounts.”
     * After uploading a PDF: “Summarize this document,” “Extract key decisions and dates.”
     * After connecting Jira: “Summarize current sprint,” “List blocked issues by owner.”

3. **Prompt insertion and execution**

   * Selecting a wayfinder suggestion either:

     * Inserts the prompt into an editable input field with any interpolated context (e.g., record IDs, file references), or
     * Executes the prompt directly and shows the generated output in the assistant panel.
   * For higher-risk actions (e.g., bulk updates), execution should always be preceded by a visible review step.

4. **Feedback and refinement loop**

   * If the user edits the inserted prompt before sending, the system can learn common modifications and propose more accurate future suggestions.
   * Dismissed or marked “not relevant” suggestions are suppressed or deprioritized in similar contexts.
   * Frequently used suggestions may be pinned or promoted to “Recommended” for that user or role.

5. **Progressive personalization**

   * Over time, the system shifts from generic starter prompts to personalized ones based on role, historical usage, and data access.
   * Examples:

     * “Prepare Monday forecast review for EMEA pipeline” for a regional sales leader.
     * “Summarize this sprint’s regressions vs. last sprint” for a QA lead.

6. **State transitions and decay**

   * Once a suggestion has been used in a session, it can be downgraded (e.g., moved into a “Recently used” or “More ideas” section) to reduce noise.
   * Wayfinders should gracefully fade or collapse once the assistant is in an active conversational flow, reappearing as subtle inline chips when appropriate rather than dominating the UI.

7. **Error and edge cases**

   * When a suggestion cannot be executed (missing permissions, disconnected integration, insufficient data), the system should:

     * Provide a clear explanation.
     * Offer an actionable next step (“Connect Jira,” “Request access to Salesforce,” “Upload a file first”).
   * Suggestions that repeatedly fail due to structural constraints should be automatically removed or reconfigured.

## Content & Interaction Guidelines

### Designing Effective Wayfinder Suggestions

* Focus on **business outcomes**, not technical commands.

  * Prefer: “Summarize this quarter’s at-risk deals” over “Run a semantic analysis of accounts.”
* Make prompts **specific and scoped**.

  * Reference concrete objects (this document, selected issues, current view) instead of vague “anything” phrasing.
* Express **safety and reversibility** for sensitive operations.

  * Use language like “Propose changes,” “Draft update,” “Preview impact” rather than “Apply changes” in initial suggestions.
* Be **transparent about data access**.

  * Explicitly name key data sources and scope (e.g., “Uses Zendesk tickets from last 7 days,” “Limited to this workspace”).
  * Avoid implying access to systems or data the agent cannot see.

### Tone, Quantity, and Layout

* Limit initial suggestions to **3–5 high-value chips** to avoid overwhelm.
* Prioritize a mix of:

  * One or two canonical “hero” tasks that showcase the agent’s core value.
  * One low-risk, exploratory task (e.g., summarization, explanation).
  * One “advanced” or aspirational task for expert users.
* Use a visually consistent pattern (chips or cards) and avoid mixing multiple visual metaphors in the same surface.

### Interaction Details

* Ensure chips are fully **keyboard-accessible** and screen-reader friendly.
* Provide **hover or focus tooltips** with a short explanation and data scope for each suggestion.
* When a suggestion is executed, show a brief **“what just happened” banner** summarizing the effective prompt and context, reinforcing learnability.

## Variations

1. **Static Starter Set**

   * A curated, role-based list of suggested prompts that does not change per context.
   * Suitable for early-stage products or narrow-scope assistants.

2. **Context-Aware Suggestions**

   * Suggestions generated dynamically based on page, selection, filters, and connected data.
   * Recommended for mature, multi-module products where the assistant is embedded across workflows.

3. **Adaptive / Personalized Wayfinders**

   * Suggestions tailored by usage history, team patterns, and organization-specific templates.
   * May include per-role libraries (e.g., SDR, AE, CSM, Support Agent).

4. **Inline Wayfinders in Existing Workflows**

   * Compact chips embedded in empty tables, search results, or editors (e.g., “Ask AI to fix this query”).
   * Useful to connect AI capabilities directly to existing UI elements without opening a dedicated assistant panel.

5. **Scenario-Based Wayfinders**

   * Grouped prompts around common “jobs to be done” (e.g., “Prepare for a customer meeting,” “Close out this sprint,” “Launch a campaign”).
   * Often represented as cards containing multiple related prompt chips.

## Examples (B2B / B2C Scenarios)

* **B2B CRM / Revenue Platform**

  * After Salesforce is connected, the assistant displays:

    * “Summarize this week’s at-risk opportunities.”
    * “Draft follow-up emails for today’s meetings.”
    * “Identify deals with missing next steps.”

* **Customer Support Workspace**

  * In the ticket queue view, with several tickets selected:

    * “Summarize common themes in selected tickets.”
    * “Suggest reply drafts for all high-priority tickets.”
    * “Flag tickets that may require escalation.”

* **Project Management / DevOps Tool**

  * After connecting Jira or similar tools:

    * “Summarize current sprint status for stakeholders.”
    * “List blocked tickets and owners.”
    * “Highlight scope creep compared to original sprint plan.”

* **Analytics Dashboard (B2B SaaS)**

  * On a revenue dashboard:

    * “Explain this drop in revenue week over week.”
    * “Identify segments contributing most to churn this month.”
    * “Draft a summary of this dashboard for executive review.”

* **Prosumer Productivity App (B2C)**

  * In a personal knowledge or notes app with a new note:

    * “Summarize key points in this note.”
    * “Turn this note into a task list.”
    * “Draft a shareable summary for colleagues.”

## Instrumentation & Metrics

To understand whether wayfinders are improving trust and adoption, track:

* **Discovery & Engagement**

  * Percentage of AI sessions initiated via wayfinder suggestions vs. free-form prompts.
  * Click-through rate on individual suggestions and groups.
  * Time from assistant open to first meaningful action.

* **Effectiveness & Quality**

  * Task completion rate for sessions that began with a wayfinder suggestion.
  * User ratings or feedback on responses initiated from suggestions.
  * Drop-off points (e.g., prompts edited heavily before sending, abandoned after preview).

* **Learning & Optimization**

  * Per-role and per-context performance of suggestions (e.g., which prompts consistently lead to helpful outputs).
  * Correlation between suggestion usage and longer-term metrics (retention, feature adoption, reduced support contacts).

* **Trust & Safety Signals**

  * Incidence of user-reported “unexpected” or “unsafe” behavior following wayfinder-initiated tasks.
  * Frequency of suggestions leading to no-op responses due to missing permissions or unavailable data.

---

## Risks & Anti-Patterns

* **Over-Promising Capabilities**

  * Suggestions that imply actions the agent cannot reliably perform (e.g., “Fix all bugs in this codebase”) erode trust quickly.
  * The pattern should only surface capabilities that work consistently with production data.

* **Ignoring Data and Permissions Boundaries**

  * Suggestions that reference data sources or scopes the user does not have access to (e.g., “Summarize all company contracts” without legal access) create confusion and security concerns.

* **Clutter and Cognitive Overload**

  * Presenting too many suggestions at once, or mixing dissimilar tasks in the same cluster, can feel like noise and reduce discoverability.

* **Opaque Behavior**

  * Wayfinders that trigger complex flows without clear explanation of what will happen or which data is used can feel risky, particularly in enterprise settings.

* **Over-Reliance on Dynamic Generation**

  * Fully model-generated suggestions without guardrails may drift into irrelevant or non-compliant territory.
  * The pattern works best when grounded in a curated library with controlled variation.

---

## Accessibility Considerations

* Ensure chips and cards are navigable with keyboard and assistive technologies, with clear focus states.
* Provide descriptive text for each suggestion that can be read by screen readers, including the action and data scope.
* Maintain sufficient color contrast and avoid relying solely on color to distinguish suggestion types (e.g., “New,” “Recommended,” “Advanced”).
* Avoid motion-heavy interactions; any animations should be subtle and not essential for understanding.

---

## Implementation Notes

* **Configuration Model**

  * Represent wayfinders as structured objects (action ID, label, description, scope, required data, risk level) so they can be managed centrally.
  * Enable mapping to contexts (page, role, integration, permissions).

* **Context Engine**

  * Use a lightweight rule engine or heuristic layer to determine which suggestions to show, combining:

    * Product context (module, route, filters).
    * User context (role, permissions, region).
    * Data context (connected systems, selected objects).
    * Behavioral signals (frequently used actions, recent tasks).

* **AI Integration**

  * Templates can include placeholders (e.g., `{selected_tickets}`, `{current_dashboard}`) that the system fills before sending to the model.
  * Prompt templates should be versioned and testable, especially for regulated workflows.

* **Governance & Review**

  * Establish review workflows for new or modified suggestions, particularly those that affect data changes, external communications, or compliance-sensitive tasks.
  * Provide feature flags to enable/disable wayfinders per segment or environment.

---

## Related Patterns

* **Onboarding Overlays & Tours** – Introduce the assistant and explain its role at a higher level before wayfinders guide concrete actions.
* **Prompt Actions / Quick Actions** – One-click triggers for common AI tasks, often used after the user is familiar with the assistant.
* **Tuners & Governors** – Controls for adjusting agent behavior (tone, scope, risk level) and enforcing organizational guardrails.
* **Preview & Confirmation Flows** – Required for high-impact actions initiated via wayfinders (e.g., bulk updates, external messages).

---

## Checklist

* [ ] The assistant never appears as a blank prompt in critical entry points; at least 3–5 relevant wayfinder suggestions are present.
* [ ] Each suggestion is action-oriented, scoped, and clearly communicates what data will be used.
* [ ] High-risk suggestions include preview and confirmation steps and are visually differentiated from low-risk, exploratory actions.
* [ ] Suggestions adapt based on context (page, selection, data sources) and do not reference unavailable or unauthorized data.
* [ ] Usage and outcome metrics are instrumented to continuously refine which suggestions appear for which roles and scenarios.
* [ ] Users have explicit ways to dismiss or provide feedback on irrelevant suggestions, feeding back into the recommendation logic.
